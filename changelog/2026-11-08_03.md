## Why Care?

Only people marked `"admin": true` in the `PEOPLE` secret could add or remove teammates. A Worker secret can't be read back, so making someone an admin later meant re-entering every key in it. That left people who joined from the landing page with no way to become an admin.

## What's New?

- **`members.admin`.** Whoever runs the deployment can make a landing-page connector an admin with one command:
  `npx wrangler d1 execute <db> --remote --command "UPDATE members SET admin = 1 WHERE self_serve = 1 AND email = 'you@example.com'"`
- **No tool writes it**, and `query_crm` can't read the `members` table. It counts only while the row still grants access (`self_serve = 1`), so revoking a connector also drops its admin rights.
- People added from chat with `add_person` are still never admins.

## Under the Hood

- Migration `0010_member_admins.sql` adds `admin INTEGER NOT NULL DEFAULT 0` to `members`. The connector's `Person` carries `admin` from that row.
- On servers with `SELF_SERVE: "teams"` (see `2026-11-08_02`), whoever starts a team is its admin automatically; this flag is for the deployment's own home team.
